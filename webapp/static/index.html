03 / Capabilities

WHAT THE
SYSTEM SEES.

Five connected layers, each computed from the footage and the calibrated court — not from hand-entered statistics.

01

Perception

Player & ball intelligence

Detection and tracking identify players, their pose keypoints and the ball across the rally. A dedicated cleanup pass stabilises the ball track before it is used downstream.

  • PlayersYOLO detection + tracking
  • Pose17 keypoints per player
  • BallRe-detection + trajectory cleanup
02

Space

Spatial court understanding

Four annotated court corners establish a homography for the fixed camera. Every tracked position is projected into metres, so gaps, zones and movement can be measured instead of guessed.

  • Court18.0 × 9.0 m
  • MappingPer-frame homography
  • OutputMetric player coordinates
03

Relationships

Graph-based tactical structure

Player positions and pose become graph nodes. A graph attention network scores attacker–defender matchups, while an HRN branch reads the team's shape and coverage as one connected unit.

  • MatchupsGAT over player graphs
  • ShapeHRN coverage + balance
  • ActivityPretrained group-activity GAT
04

Value

Expected possession value

A physics-calibrated EPV scores the current attack: point chance, block risk, the available gap and the recommended target. The same numbers drive the on-court target call and the rendered dashboard.

  • ModelPhysics calibrated
  • ReadsPoint chance · block risk · gap
  • CallRecommended play + target zone
05

Language

AI tactical commentary

Each possession produces a time-stamped read. An offline language model writes the call when available; a deterministic template path keeps commentary working without one.

  • EngineOffline LLM or templates
  • SyncTime-stamped to the rally
  • OutputMove · possession · insight

04 / A different vantage point

THE COURT IS
A COORDINATE
SYSTEM.

Volleyball already has a geometry: six zones, a net, an attack line, three metres of separation. GritSense treats those structures as data — then layers perception, relationships and value on top.

01 Spatial intelligence

Metres, not pixels.

Court corners are projected into a homography, turning image positions into zone coordinates and measurable distances.

02 Tactical relationships

Structure over noise.

Graph attention reads relationships between players, not isolated boxes — who is blocking whom, and where the shape is stretched.

03 Possession intelligence

Value is a direction.

EPV combines the path, block risk and available gap into a point-chance read and a concrete target call.

05 / From footage to read

FIVE STAGES.
ONE RALLY.

The actual processing order. Each stage writes its output for the next; the dashboard is rendered only after the graph models and EPV are complete.

  1. 01

    Prepare

    Uploaded footage is normalised to 1920 × 1080. Audio is dropped; only the frames are analysed.

    FFmpeg · OpenCV
  2. 02

    Detect & track

    Players, pose keypoints and the ball are detected frame by frame and linked into tracks.

    YOLO · pose
  3. 03

    Clean the ball

    The ball track is re-detected and cleaned so flight paths do not carry false positives forward.

    Ball re-detection
  4. 04

    Graph & score

    Court coordinates feed GAT matchups, HRN team shape and group activity; physics scores each attack.

    GAT · HRN · EPV
  5. 05

    Render the read

    Commentary is written, the dashboard is composited and the result is encoded for the browser.

    Commentary · encode

06 / Research & engineering

BUILT AS A
LOCAL SYSTEM.

01 / Compute

Your hardware, your footage.

Deployment can select Intel Arc XPU, NVIDIA CUDA or CPU. The same pipeline runs locally; match video is not sent to a hosted inference service.

DEVICENVIDIA RTX (CUDA)
02 / Calibration

One fixed camera is enough.

Court corners from the project's annotation file give each frame a homography. Frames without their own corners reuse the last calibrated one.

SPACE18 × 9 m · four corners
03 / Language

Commentary with a fallback.

When the offline model and its cache are available, it writes the read. Otherwise, the deterministic template engine produces the same time-stamped structure.

MODEOffline LLM / template
